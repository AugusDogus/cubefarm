# Information and interaction: adversarial review

Reviewer: independent UI/UX research agent. Reviewed and independently re-reviewed 2026-10-04. Scope: `App.tsx`, components, disclosure rules, styles, save interaction, and existing interaction tests. This is a source-informed inspection, not an observed human playtest or an accessibility certification. No user save was opened, altered, or reset.

## Retrieved evidence

All successful sources below were fetched over HTTPS with HTTP 200 during this review. Quotes support principles, not the game's precise thresholds, sizes, or timer constants.

1. [Jakob Nielsen, Progressive Disclosure, NN/g, 2006](https://www.nngroup.com/articles/progressive-disclosure/). “Initially, show users only a few of the most important options.” Counterweight: “You have to disclose everything that users frequently need up front.” The article also warns that designs beyond two disclosure levels typically have low usability. It expressly recommends observational testing to determine whether grouping matches actual tasks.
2. [Aurora Harley, Visibility of System Status, NN/g, 2018](https://www.nngroup.com/articles/visibility-system-status/). “Communicating the current state allows users to feel in control of the system, take appropriate actions to reach their goal.” This supports visible costs, bottleneck advice, and persistent recovery messages. It does not justify reading every changing number aloud.
3. [Game Accessibility Guidelines, contextual in-game help](https://gameaccessibilityguidelines.com/include-contextual-in-game-helpguidancetips/). “Gradually introducing concepts to the player during gameplay not only gives greater context, but also avoids overburdening gamers ... with too much information at once.” Industry guidance, not a controlled study of this game.
4. [Game Accessibility Guidelines, simple controls](https://gameaccessibilityguidelines.com/ensure-controls-are-as-simple-as-possible-or-provide-a-simpler-alternative/). “More complex control schemes require higher degrees of both motor and cognitive skill.” It allows necessary complexity and objects to controls being more complex than needed. This supports bulk operations and named allocation plans while preserving advanced input.
5. [Game Accessibility Guidelines, repeated inputs](https://gameaccessibilityguidelines.com/avoid-repeated-inputs-button-mashing-quick-time-events/). “If you can’t avoid QTEs or button mashing actions, include a setting to simplify or skip/disable them.” Cube Farm is not a QTE game; the relevant implication is reducing repetitive motor work, not claiming that any clicking is prohibited.
6. [Game Accessibility Guidelines, text at the player's pace](https://gameaccessibilityguidelines.com/allow-players-to-progress-through-text-prompts-at-their-own-pace/). “Instead of a timer, dismiss information on a player action.” Supports indefinite narrative decisions and a correspondence archive. Does not require every purchase acknowledgement to remain indefinitely.
7. [Game Accessibility Guidelines, readable font size](https://gameaccessibilityguidelines.com/use-an-easily-readable-default-font-size/). “Allowing a choice of font size is the ideal solution.” The page's 28px example is for a 1080p television interface and must not be misrepresented as a desktop requirement.
8. [W3C, Understanding WCAG 2.2 SC 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html). “For any action that involves dragging, provide a simple pointer alternative.” It explicitly accepts a range track that can be tapped and a text input beside a slider. Native range controls are not automatically a dragging-only violation.
9. [W3C, Understanding WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Pointer targets must be “at least 24 by 24 CSS pixels” subject to enumerated exceptions, including sufficient spacing. The CSS alone cannot establish actual rendered target spacing or certify compliance.
10. [W3C, Understanding WCAG 2.2 SC 3.2.2](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html). Forewarn users if input changes their context. Updating another number is not necessarily a change of context. This is useful caution for automatic allocation changes, not grounds for a false conformance failure.

Access limits: two guessed Game Accessibility Guidelines detail URLs and two guessed NN/g URLs returned 404. They were not used as evidence; working detail URLs were discovered from the guidelines index. No empirical source establishes that Cube Farm's layout is fun, optimal, or award quality.

This review does not justify declaring the interface frictionless or award quality.

## Late agency addition: independent UX review

The user subsequently requested action on late-game agency. This review covers the added `NetworkInvestment` section, commissioning, standing investment, computing priorities, and knowledge reserve. It reuses retrieved sources [1–9] above, rather than claiming a new source proves these exact mechanics. This reviewer inspected current code and rendered fixtures only. The parent owns current browser verification; no browser or user save was touched here.

Highest concrete findings sent to the parent:

1. A disabled launch says only “No launch within current reserves,” while available knowledge and spendable cash appear outside this section. A player cannot distinguish a knowledge shortage, cash shortage, configured reserve, or lifetime launch limit. Show compact available-budget values and the actual minimum next-office requirement or limit. This is visibility of system status [2], not a request for another tab.
2. The “Extra compute / s” label is inaccurate: `computeSpentRate` includes natural replication compute, even with Standard routing. Rename it “Compute spent / s” or calculate only routing expenditure. A forecast must communicate the resource it actually measures [2].
3. Routing cost descriptions appear only for the current mode. Selecting Parallel filing starts knowledge spending immediately, before revealing its numerical cost. Expose the three tradeoffs before activation with compact copy or clearly introduced comparison. Keeping a choice one-click is reasonable; hiding its consequence until afterward is not.
4. “Research first” protects the cheapest available procedure against automatic commissioning only. It does not protect against Parallel filing or manual launch beyond the configured global reserve. Clarify that scope explicitly. A single knowledge-reserve input is valuable, but the automatic policy's extra buffer must not be confused with that global input.
